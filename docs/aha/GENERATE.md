# Generating the AHA failure dataset (for the SMD/RND detector benchmark)

Goal: produce **dense success + failure trajectories** (per-step 7-DOF Franka state +
multi-camera RGB + binary label + failure type) that `scripts/ingest_aha.py` loads into the
drishti Store, so `scripts/eval_aha.py` can measure how well SMD+RND catch the labeled
failures.

AHA ships **no downloadable trajectories** — the dataset is procedurally generated by
FailGen (perturb a successful RLBench demo → labeled failure). Generation is **CPU +
OpenGL, not GPU** (zero NN inference), embarrassingly parallel, headless via `xvfb`. The
real cost is the one-time install and disk. Run everything on the Prime Intellect pod
(where `rlbench` + a GPU for the vision embedding are available); pull only `data/obs.db` +
`data/obs_blobs/` + `data/calib/report_aha.json` back to the Mac, into a per-campaign directory
(`data/aha_v2/`, `data/aha_breadth/`, …).

## 1. Install (one-time, Ubuntu pod)

```bash
git clone https://github.com/NVlabs/AHA.git && cd AHA
conda create -n aha python=3.10 -y && conda activate aha

# CoppeliaSim v4.1 (headless GL)
wget https://downloads.coppeliarobotics.com/V4_1_0/CoppeliaSim_Edu_V4_1_0_Ubuntu20_04.tar.xz
tar -xf CoppeliaSim_Edu_V4_1_0_Ubuntu20_04.tar.xz
export COPPELIASIM_ROOT=$PWD/CoppeliaSim_Edu_V4_1_0_Ubuntu20_04
export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:$COPPELIASIM_ROOT
export QT_QPA_PLATFORM_PLUGIN_PATH=$COPPELIASIM_ROOT

git clone https://github.com/stepjam/PyRep.git && pip install ./PyRep
git clone -b peract https://github.com/MohitShridhar/RLBench.git && pip install -e ./RLBench
cd aha/Data_Generation/rlbench-failgen && pip install -e . && cd -
```

## 2. Trim the FailGen config (RGB-only, 2 cameras — cuts disk + render time)

FailGen reads a per-task YAML at `aha/Data_Generation/rlbench-failgen/failgen/configs/<task>.yaml`.
We only need RGB from **front + wrist**; disable depth/mask/point_cloud and the other cameras.
For each task you generate, set its `data:` block to:

```yaml
data:
  save_path: /data/aha_out          # gen_aha.py --save-path overrides this at runtime
  image_size: [256, 256]
  images:   { rgb: True, depth: False, mask: False, point_cloud: False }
  cameras:  { front: True, wrist: True, overhead: False,
              left_shoulder: False, right_shoulder: False }
```

(Point clouds + masks are the disk hogs; RGB-only keeps episodes small. `front` = global
scene, `wrist` = contact view — the two we embed for RND.)

## 3. Generate dense success + failure demos

The stock `ex_custom_data_generator.py` saves *keyframes only* (no per-step state), so use
our driver `scripts/gen_aha.py` (copy it into the pod checkout; it uses the wrapper's
`get_success()` / `get_failure()` with `save_keyframes_only=False`):

```bash
# start narrow: a few tasks, the 4 modes that trigger reliably, ~20 successes each
xvfb-run -a -s "-screen 0 1400x900x24" python scripts/gen_aha.py \
  --tasks pick_and_lift pick_up_cup stack_blocks \
  --failtypes grasp slip translation_z wrong_sequence \
  --episodes 20 --fail-episodes 4 --save-path /data/aha_out
```

`--episodes` = success demos per task; `--fail-episodes` = failure demos **per mode** (defaults to
`--episodes`, which is almost never what you want — failures are the expensive half). Use the 4
modes above: `wrong_object` and the `rotation_*` modes are retry-hungry (`--max-tries`, default 5)
and stalled throughput on every campaign we ran. A task that doesn't support a mode is skipped with
a message, and a task that throws is caught so it can't kill the batch.

Output tree (what `ingest_aha.py` globs — `*/*/episodes/episode*/low_dim_obs.pkl`):

```
/data/aha_out/<task>/success/episodes/episode<N>/{low_dim_obs.pkl, front_rgb/, wrist_rgb/}
/data/aha_out/<task>/<fail_type>/episodes/episode<N>/{low_dim_obs.pkl, front_rgb/, wrist_rgb/}
```

Parallelize across tasks with one process per task (generation is CPU-bound).

## 4. Ingest → Store, then evaluate (on the pod)

```bash
# in the drishti repo/venv on the pod (needs rlbench importable to unpickle demos):
PYTHONPATH=. python scripts/ingest_aha.py --data /data/aha_out --cams front wrist --embed-stride 8

# optional but recommended: re-embed the saved frames with the other encoders (GPU-fast on the pod)
PYTHONPATH=. python scripts/embed_offline.py --encoder dinov2-cls  --cams front wrist
PYTHONPATH=. python scripts/embed_offline.py --encoder dinov2-mean --cams front wrist

PYTHONPATH=. python scripts/eval_aha.py --source aha --split episode --seed 0   # headline
PYTHONPATH=. python scripts/eval_aha.py --source aha --split task    --seed 0   # cross-task stretch
```

`ingest_aha.py` writes `data/obs.db` (or wherever `DRISHTI_OBS_DB_URL` points) plus
`data/obs_blobs/<run>/` — that blob path is hardcoded in the ingester, so ingest one campaign at a
time and move the directory afterwards. Per run it stores:

- **State: the full 30-D proprioceptive superset** — `joint_positions(7) + joint_velocities(7) +
  joint_forces(7) + gripper_open(1) + gripper_joint_positions(2) + gripper_touch_forces(6)` — with a
  `meta.field_slices` offset map so any subset is an **offline** column-slice via
  `eval_aha.py --state-fields ...` (e.g. the 17-D proprio-only slice
  `joint_positions joint_velocities gripper_open gripper_joint_positions`). Override the captured
  set with `--fields`. `task_low_dim_state` is deliberately **excluded** — it leaks ground-truth
  object pose and the detector would cheat. **Record which slice a result used**; it changes SMD's
  AUC by up to 0.4 (see `RESULTS.md`, v2 section).
- **Embeddings:** SigLIP (`google/siglip-base-patch16-224`) per embed-frame into
  `data/obs_blobs/<run>/embed_<f>.npy`. `--embed-stride N` embeds every Nth frame — RND carries the
  last embedding forward, so sparse is fine and it cuts CPU embedding cost by Nx.
- **Raw JPEGs** at the embed steps, **by default**, so encoder swaps are an offline re-embed
  (`embed_offline.py` → `embed_<f>_<encoder>.npy`, selected later with `eval_aha.py --embedder`).
  Pass `--no-frames` to skip them — but then you are locked to SigLIP for that capture.

## 5. Pull results to the Mac

```bash
rsync -avz pod:.../drishti/data/obs.db          data/<campaign>/
rsync -avz pod:.../drishti/data/obs_blobs/      data/<campaign>/obs_blobs/
rsync -avz pod:.../drishti/data/calib/report_aha.json data/calib/
```

Then view runs/replays in the dashboard locally, or re-run the eval against the pulled `obs.db` by
pointing both env vars at the campaign directory (this is how every table in `RESULTS.md` is
reproduced — `eval_aha.py` reads blobs from `DRISHTI_BLOB_DIR`, `Store` reads
`DRISHTI_OBS_DB_URL`):

```bash
DRISHTI_OBS_DB_URL="sqlite:///data/<campaign>/obs.db" DRISHTI_BLOB_DIR="data/<campaign>/obs_blobs" \
  PYTHONPATH=. python scripts/eval_aha_seeds.py --source aha --split episode --train-frac 0.75 --k 8 \
  --embedder dinov2-cls --state-window 4 --embed-window 2 \
  --state-fields joint_positions joint_velocities gripper_open gripper_joint_positions --task <TASK>
```

`eval_aha_seeds.py` fixes the train/eval split once (`--split-seed`) and refits RND under K torch
seeds, printing mean ± std per signal and per failure mode. **Caveat:** `RND.__init__` now pins its
own seed (`seed=0`), which overrides the per-seed `torch.manual_seed(s)` in the loop — so `--k 8`
currently prints ±0.00 and gives a single-seed number. Pass `seed=None` through if you want the
seed average back. `eval_aha.py` is the single-run version
and is the one that writes `data/calib/report_aha.json` (`--out` to redirect). Read the report:
`auc_fail_vs_success` is the headline; `auc_per_signal` splits SMD vs RND; `per_failure_mode` shows
which modes each detector catches — on the 4 modes above, expect RND to lead on `grasp` (is the
object actually in the gripper?), SMD on `slip` and the kinematic `translation_*` offsets, and
neither per-frame on `wrong_sequence` until you add `--state-window`/`--embed-window`.
